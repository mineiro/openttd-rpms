# OpenGFX2 Classic packaging research

Checked 2026-09-11 against the upstream release, its tagged source, and CDN metadata. This records source and licensing findings; build and publication status belongs in the packaging validation results.

## Release and source provenance

[OpenGFX2 0.8.1](https://github.com/OpenTTD/OpenGFX2/releases/tag/0.8.1) is the latest stable release, published 2025-12-15. Its tag resolves to commit `013cbc9e700c796af001a381a2d93592d49146ac`. The GitHub API records the Classic binary tar as 16,742,400 bytes, SHA256 `2f4d0d8cd82b9b15d7c5a742581bfd11a08d4fd54fc0743f1f8a1032e3b5eeaf`. This is useful as an upstream reference, not as a substitute for building the RPM from source.

The [official CDN manifest](https://cdn.openttd.org/opengfx2_classic-releases/0.8.1/manifest.yaml) lists `opengfx2_classic-0.8.1-all.zip`, 10,856,877 bytes, SHA256 `37c29e419593e583bf718c50c2c95311a1dfc5398c18d95c1bbe6f3b91d6b4c0`. Its `dev_files` field is empty. A HEAD request for the conventional `opengfx2_classic-0.8.1-source.tar.xz` returned HTTP 403. Therefore this release has no manifest-verified CDN source archive; do not construct a presumed source URL or silently package its binary ZIP through the generic source downloader.

The downloaded GitHub archive of the pinned commit extracted under `OpenTTD-OpenGFX2-013cbc9`. The local archive was 2,314,698 bytes with SHA256 `61b04441966bcfd34301e097973f3dc9c8c4b5932627cd57768f3ce2de84536b`. It contains **1,982 Git LFS pointers**, not the corresponding graphic assets. The [tagged attributes file](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/.gitattributes) marks PNG, PDN, GIF, ASE and Blender files as LFS-managed. A build source bundle must materialize the required LFS objects, verify their declared SHA256 and size, and include the editable upstream originals when distributing the corresponding source. A SHA256 of the small GitHub archive alone does not authenticate the separately fetched asset bytes.

Research files and the parent's shared extraction are under `.cache/opengfx2-research/`. Generated GitHub archive bytes/root names depend on the download endpoint; production lock metadata must match the endpoint actually used by the source preparation script.

## Licenses and notices

The [tagged LICENSE](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/LICENSE) is GPL version 2. The [English strings](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/baseset/lang/english.lng) describe the GRF and normal Classic OBG as GPL v2+, while the general description and OBG generator's fallback say version 2. Original OpenGFX-derived assets are also present; upstream's [credits](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/credits.md) explicitly retain that project's authors. Use GPL version 2 as the common permitted distribution version rather than relying on the broader translated UI descriptions to relicense inherited content. Preserve `LICENSE` and `credits.md` with `%license`, and ship `README.md` and `CHANGELOG.md` as documentation.

The [font generator](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/graphics/fonts/charactergrab.py) rasterizes OpenTTD Sans, Small, Serif and Mono from the separately cloned OpenTTD-TTF repository into reusable glyph sprites. Its root GPL license is not the whole licensing picture: the SFD font sources embed an explicit SIL Open Font License 1.1 notice and credit Richard Wheeler (Zephyris). This is the same discrepancy already documented for this repository's engine package in `docs/packaging-research.md`. Keep both the GPL notice and the font-specific OFL notice; do not describe the discrepancy as verified dual licensing. A conservative aggregate for the graphics package retaining the reusable font glyphs is `GPL-2.0-only AND OFL-1.1`.

The latest font commit preceding the OpenGFX2 release timestamp is [`0fc6324b32ce49b1eb3f37bf8ad36b598f044e79`](https://github.com/OpenTTD/OpenTTD-TTF/tree/0fc6324b32ce49b1eb3f37bf8ad36b598f044e79), dated 2025-08-26. This is a reproducible candidate dependency pin, not proof of the exact font revision upstream used for its binary. All four `OpenTTD-{Sans,Small,Serif,Mono}.sfd` files at that commit contain the same OFL declaration in their `LangName` metadata. The [font README](https://github.com/OpenTTD/OpenTTD-TTF/blob/0fc6324b32ce49b1eb3f37bf8ad36b598f044e79/readme.md) identifies the FontForge SFD files as master sources. Include them in the SRPM, rebuild the needed TTFs, and extract the full embedded OFL text and copyright to an installed license file. Font revision changes should receive the existing font-license review treatment.

OFL distinguishes ordinary artwork made using fonts from redistributed reusable font software: [its FAQ](https://openfontlicense.org/ofl-faq/) permits graphics freely, while font bundling must preserve the relevant notices. Here the output is reusable game font glyphs, so keeping the font notices avoids relying on the ordinary-artwork exemption. No separate sound files or additional CC licenses were found in the 0.8.1 source tree. The tram-bell CC0 credit visible on current `main` is later content and must not be attributed to the 0.8.1 baseset without evidence.

## Variant, compatibility and installation

The [release README](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/README.md) describes Classic as the complete 8-bit normal-zoom set. High Def is a distinct, incomplete higher-resolution variant and is outside this package's scope. The baseset build produces `opengfx2_8.obg` and six GRFs: `ogfx21_base_8`, `ogfx2c_arctic_8`, `ogfx2h_tropical_8`, `ogfx2t_toyland_8`, `ogfx2i_logos_8`, and `ogfx2e_extra_8` (each with `.grf` extension).

Install these together in a dedicated system baseset subdirectory such as `/usr/share/openttd/baseset/opengfx2-classic/`. This keeps the files distinct from Fedora's original OpenGFX and allows both sets to remain installed. It is an alternative selected in **Game Options → Graphics → Base graphics set**, not an upgrade of the `openttd-opengfx` RPM and not a gameplay NewGRF. Do not add `Obsoletes` or delete an existing user's graphics selection.

OpenTTD has supported native baseset parameters since 14.0; this package's 16.0 beta can use them without the old Settings NewGRF workaround. Upstream specifically [recommended OpenGFX2 for OpenTTD 15](https://www.openttd.org/news/2025/12/08/openttd-15-0-rc1) because original OpenGFX lacks sprites for some newer engine features. OpenGFX2's [0.8 changelog](https://github.com/OpenTTD/OpenGFX2/blob/0.8.1/CHANGELOG.md) records new bridge overlays, city/town font icons and badges-menu symbols. The graphics release is independent of the engine beta release schedule.

The upstream Makefile clones and pulls an unpinned font repository as part of graphics generation. Source preparation must pin and provide that dependency before the RPM build and remove those network operations. Build only the Classic target. Retain an installed-engine discovery check using an isolated empty home, verify all six descriptor references and their GRF-format MD5 values, and explicitly load Classic so an installed original OpenGFX cannot mask a missing or broken new set.
